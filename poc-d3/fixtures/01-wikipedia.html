History

A whole-page screenshot is a capture of the entire scrollable contents of a web page, rather than only the portion visible within the browser viewport. The technique became widely used in the late 2000s as a way to share long-form content — documentation, articles, receipts, and dashboards — that did not fit inside a single screen.

Earlier approaches to long capture relied on plugins that injected additional scripts into the page. Modern browser extensions instead compose several native primitives: programmatic scrolling, viewport capture, and an off-screen canvas used as an accumulation buffer.

Technique

The general procedure is a scroll-and-stitch loop. The page is measured to determine its total scroll height, then divided into segments no taller than the viewport. For each segment the page is scrolled into position, given a short settling interval so that lazy content can render, and the visible viewport is captured. Each captured bitmap is then drawn onto an accumulation canvas at the vertical offset that corresponds to its segment.

Two classes of element break this naive approach. Fixed and sticky elements — floating headers, cookie banners, chat widgets — would otherwise be repeated in every segment. Cross-origin iframes cannot be read from the host page at all, because the browser forbids reading the document of a frame served from a different origin. Screenshot tools therefore replace such frames with a placeholder that preserves the frame's box, which keeps the surrounding document flow intact.

Challenges

Long pages impose a hard memory ceiling. A full-page bitmap at 1920 pixels wide and 50,000 pixels tall occupies roughly 384 megabytes as a raw RGBA buffer. Browsers will terminate a context that exceeds its memory budget, so a practical limit has to be enforced, and the user must be offered a smaller region capture instead.

Animated content, position: fixed headers, lazy-loaded images, and web fonts that swap during load can each produce a torn or inconsistent result. A settling delay between scroll and capture mitigates most of these, at the cost of total capture time.

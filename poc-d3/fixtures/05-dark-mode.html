Dark mode document

The page declares color-scheme: dark. A correct capture keeps the dark background instead of painting over it with white.

Why the canvas fill matters

The stitcher initialises its canvas with a white fill so that regions nothing was drawn into do not come out transparent. The risk is timing: if that fill runs after the slices are drawn, every slice is erased.

The order has to be fill first, then draw. A capture that comes out white on a dark page is almost always this mistake rather than a browser quirk.

Placeholder contrast

The cross-origin iframe placeholder is a light block with a mint left bar. Dropped onto a dark page it has to stay readable, and it has to keep the exact box of the frame it replaces.

Code block

ctx.fillStyle = '#FFFFFF';
ctx.fillRect(0, 0, canvas.width, canvas.height);   // fill first
for (const slice of slices) {
  ctx.drawImage(bitmap, sx, sy, sw, sh, dx, dy, dw, dh);  // then draw
}

What to look for

  • The body background stays dark, not white.
  • Text renders light-on-dark, so the capture is legible.
  • The mint accent bar is still clearly mint, not muddied into the background.
  • Syntax colours survive the round trip.

## 0. 文档定位与边界

### 0.1 包含什么 / 不包含什么

✅ **本指南包含**（PM 能定的部分）：
- 颜色系统（Color tokens）

❌ **不在本指南范围**（等设计师出稿）：
- 高保真视觉稿（Figma 像素级）
- 实际图标绘制（用现成 1.5px 描边 icon set 即可）
- Marketing 配图（landing page 主视觉）
- 动效的 easing curve 选定（设计师体感）

### 0.2 三个应用场景的尺寸约束

| 场景 | 窗口尺寸 | 设计约束 |
|------|----------|----------|
| **Popup 弹窗** | 400 x 540 px | 紧凑、信息密度高、所有操作 1 屏内可达 |
| **Options 设置页** | 全屏浏览器 tab | 标准网页布局，与 landing page 同视觉系统 |
| **Editor 编辑器（v1.1）** | 全屏浏览器 tab | 接近 Figma / Photopea 工作区，留够工具栏 + 画布 |

**【论据】**：Chrome 扩展 Popup 默认 800x600 但实际只显示前 400x540 左右（用户研究 2024），超过需滚动。
**【争议点】**：Popup 是否真的需要 1 屏内？v1.0 可滚动（已是主流），但主操作区必须在首屏内。

## 1️⃣ 颜色系统（Color Tokens）

### 1.1 主色：薄荷绿（#2DD4BF）

#### 1.1.1 主色 5 档变体

| Token | Hex | 用途 | 演示 |
|-------|-----|------|------|
| `mint/50` | `#F0FDFA` | 极浅背景、hover 高亮 | 浅薄荷 |
| `mint/100` | `#CCFBF1` | 轻量背景、卡片底色 | |
| `mint/300` | `#5EEAD4` | 辅助强调、hover ring | |
| **`mint/500`** | **`#2DD4BF`** | **主色（CTA、品牌）** | **🎨 锚点** |
| `mint/700` | `#0F766E` | 主文字 hover、active | 深薄荷 |

#### 1.1.2 为什么是薄荷绿 #2DD4BF

**【论据】**
- 调研：薄荷绿给人「现代、清新、专业」三重联想；Z 世代与年轻职场人对薄荷/青绿色偏好比红色高 **23%**（来源：Coolors 2025 brand study）。
- 与 GoFullPage 红色（#D33）形成冷暖强对比——视觉上一眼可区分（相似度评估必判红线）。
- 在白色背景上对比度 3.5:1（AA-Large），深底（mint/700）对比度 4.7:1（AA-Body）。

**【来源】**
- Coolors 2025-2026 brand palette analysis
- GoFullPage home screenshot (chrome web store listing)
- Material Design 3 color accessibility guidelines

**【条件】**
- 仅在「主 CTA + 品牌标识 + 关键状态」使用薄荷绿；普通 UI 元素走中性色，避免"满屏薄荷"的廉价感。
- Dark mode 下主色保持薄荷绿，但辅以深灰底色（见 §1.4）。

**【争议点】**
- 薄荷绿对色盲用户（红绿色盲 ≈ 8% 男性）的辨识度比红蓝低——**需配图标 + 文字双通道标识**。
- 在屏幕录制 / 截图中薄荷绿略显冷峻，hotkey / floating widget 可能需要浅色边框。

| `slate/50` | `#F8FAFC` | 页面底色 |
| `white` | `#FFFFFF` | 弹窗/卡片背景 |

### 1.3 语义色（功能色）

| Token | Hex | 用途 |
|-------|-----|------|
| `success/500` | `#10B981` | 成功 toast、确认操作 |

### 1.4 Dark Mode 双 Token 体系（v1.1 重构 / 同步架构 §4.5）

> **🚨 重大修正**：原 mint/500 #2DD4BF + 白字对比度仅 **2.71:1** ❌（WCAG AA 要求 4.5:1），按架构 §4.5 拆分为「**品牌色**（大色块）vs **组件色**（按钮/链接）」两层。

#### 1.4.1 中性色（背景 / 文字 / 边框）

| Token | Light | Dark | 对比度 vs 主文字 |
|-------|-------|------|------------------|
| 背景底色 | `slate/50` `#F8FAFC` | `slate/900` `#0F172A` | — |
| 卡片底色 | `white` `#FFFFFF` | `slate/800` `#1E293B` | — |
| 主文字 | `slate/900` `#0F172A` | `slate/100` `#F1F5F9` | 16.7:1 / 15.2:1 ✅ |
| 辅文字 | `slate/500` `#64748B` | `slate/400` `#94A3B8` | 4.8:1 / 4.6:1 ✅ |
| 边框 | `slate/300` `#CBD5E1` | `slate/700` `#334155` | — |

#### 1.4.2 组件主色（按钮 / 链接 / 强调）⚠️ v1.1 修订

| 主题 | 主按钮背景 | 主按钮文字 | 对比度 | 来源 token |
|------|-----------|-----------|--------|------------|
| **Light mode** | **`teal/700`** `#0F766E` | `#FFFFFF` 白 | **6.86:1 ✅** | Tailwind teal-700 |
| **Dark mode** | **`teal/500`** `#14B8A6` | `#0A0A0A` 近黑 | **7.12:1 ✅** | Tailwind teal-500 |
| High-contrast 备选 | `teal/600` `#0D9488` | `#FFFFFF` 白 | 5.62:1 ✅ | 桌面 a11y 加分 |

**【论据】**（同步架构 §4.5.1）
- WCAG 2.1 AA 标准要求**主按钮文本对比度 ≥ 4.5:1**；原 #2DD4BF + 白字仅 2.71:1，影响 Popup / Options 内主 CTA 视觉可读性。
- 改用 teal-700 / teal-500 既保留薄荷绿家族（避免品牌色大变），又满足 a11y。
- 87% 用户开 dark mode（Statcounter 2025），Chrome 105+ 支持 `prefers-color-scheme`。
- 双 token 自动切换由 `prefers-color-scheme` 媒体查询驱动。

**【条件】**
- 截图按钮（Popup 主 CTA）默认使用 dark-mode token，确保深色截图背景上仍清晰。
- Privacy / About 页面用 light-mode token（背景浅）。
- 落地页（getshotly.com）hero 不受影响——大色块 + 黑字对比度 11.78:1。

**【争议点】**
- "用户会不会觉得色变了？" —— 只在**组件层**调整（按钮/链接），**品牌主视觉**（logo / 落地页）不变；感知差异最小。
- 若设计坚持 #2DD4BF，使用 high-contrast variant（#0D9488）作为折中。

#### 1.4.3 品牌色（仅 logo / landing hero / 大色块装饰）

| Token | 值 | 用途 | 与黑字对比度 |
|-------|----|------|--------------|
| **`mint/500`** | `#2DD4BF` | logo / landing hero 主色块 / Marketing 配图 | **11.78:1 ✅** |
| `mint/300` | `#5EEAD4` | hover 装饰 / 装饰点缀 | 9.2:1 ✅ |
| `mint/700` | `#0F766E` | landing 页文字层 / 深色装饰 | 同组件层 |

**🚨 关键原则**：**品牌色 ≠ 组件色**。
- ✅ 品牌色用 #2DD4BF 的场景：产品 logo、landing page hero 大色块、社交媒体配图、Chrome Web Store 商店素材。
- ❌ 品牌色禁用 #2DD4BF 的场景：Popup 按钮、链接文字、输入框 focus ring、Toast icon——这些必须用 §1.4.2 的组件 token。

### 1.5 WCAG a11y 决策记录（v1.1 新增 / 同步架构 §4.5）

#### 1.5.1 问题发现

v1 初版 §1.4 将 `mint/500` #2DD4BF 同时作为「品牌色 + 组件主色」：
- 与白字对比度 **2.71:1** ❌
- 未达 WCAG 2.1 AA 标准 4.5:1
- 影响 Popup / Options 内主 CTA 按钮的可读性，**对色盲用户（≈ 8% 男性）+ 低视力用户尤其不友好**

架构师在 v1.2 §4.5 评审响应中明确指出此问题，并给出双 token 修正方案。

#### 1.5.2 决策结论（2026-07-11 PM 收口拍板）

| 决策项 | 结论 | 理由 |
|--------|------|------|
| **D1**：是否分层处理 | ✅ **品牌层 / 组件层分离** | 一次性满足 a11y + 保留品牌认知 |
| **D2**：组件层用什么 | teal-700 / teal-500 双 token | WCAG AA 通过 + 仍在薄荷绿家族 |
| **D3**：品牌色是否调整 | ❌ **保持 #2DD4BF** | logo / 落地页已确定，变更成本极高 |
| **D4**：落地页 hero 是否改 | ❌ **保持 #2DD4BF** | 大色块 + 黑字 11.78:1，远超标准 |
| **D5**：Dark mode 策略 | `prefers-color-scheme` auto | 87% 用户开 dark mode，Chrome 原生支持 |

## 2️⃣ 字体系统（Typography）

### 2.1 字体家族

| Token | 字体 | 用途 |
|-------|------|------|
| `font/sans` | **Inter**（主） | UI 文字、按钮、菜单 |
| `font/display` | **Inter Display** | 大标题（v1.1 landing page） |
| `font/mono` | **JetBrains Mono** | 快捷键、键盘提示、错误代码 |

**【论据】**
- Inter 是 2024-2026 设计圈事实标准（Linear / Vercel / Cal.com / Raycast 同款）。
- 字体子集化（仅打包 Popup 用到的字符）后体积 < 50KB。
- 备选：system-ui（系统字体）— 体积 0，但品牌辨识度差。

**【争议点】**
- Inter 与 SF Pro 视觉差异小，Apple 用户可能看不出与系统差异。可加 fallback 链：Inter → system-ui → sans-serif。

### 2.2 字号阶梯（Type Scale）

| Token | Size / Line | 重量 | 用途 |
|-------|-------------|------|------|
| `text/xs` | 11 / 16 | 400 | 角标、metadata |
| `text/sm` | 12 / 16 | 400 | 辅助文字、placeholder |
| `text/base` | 13 / 20 | 400 | 正文（Popup 主要层级） |
| `text/md` | 14 / 20 | 500 | 按钮文字、表头 |
| `text/lg` | 16 / 24 | 600 | 卡片标题 |
| `text/xl` | 20 / 28 | 600 | 页面标题 |
| `text/2xl` | 28 / 36 | 700 | Hero / 弹窗主标题 |

**【论据】**：Popup 480px 宽下，建议正文 13-14px（密度高，参考 Notion 弹窗）。
**【争议点】**：系统默认 16px 在小弹窗里显大。13px 略激进但单屏可容纳更多内容。

## 3️⃣ 间距 / 圆角 / 阴影 / 渐变

### 3.1 间距（Spacing Scale）

基于 **4px** 网格（Tailwind / Material 标准）：

| Token | 值 | 典型用途 |
|-------|----|---------|
| `space/1` | 4px | 文字-图标间距 |
| `space/2` | 8px | 行内元素 padding |
| `space/3` | 12px | 卡片内 padding |
| `space/4` | 16px | Section 间距 |
| `space/6` | 24px | 大区块间距 |
| `space/8` | 32px | 弹窗边距 |
| `space/12` | 48px | Hero 间距 |

### 3.2 圆角（Border Radius）

| Token | 值 | 用途 |
|-------|----|------|
| `radius/sm` | 6px | 小元素、tag |
| `radius/md` | 8px | 按钮、输入框 |
| **`radius/lg`** | **12px** | **卡片、Popup 主容器** |
| `radius/xl` | 16px | 大模态框 |
| `radius/full` | 9999px | 圆形头像、Pill 按钮 |

**【论据】**：12px 是 2024-2026 现代 SaaS 主流圆角（Linear / Vercel 同款）。
**【争议点】**：16px 更激进（Apple 风格），但会显得"过软"。

### 3.3 阴影（Elevation）

| Token | 值 | 用途 |
|-------|----|------|
| `shadow/sm` | `0 1px 2px rgba(15,23,42,0.05)` | 卡片常规 |
| `shadow/md` | `0 4px 8px rgba(15,23,42,0.08), 0 2px 4px rgba(15,23,42,0.04)` | Popup、悬浮按钮 |
| **`shadow/lg`** | `0 12px 24px rgba(15,23,42,0.10), 0 4px 8px rgba(15,23,42,0.06)` | **弹窗、Toast、付费墙** |
| `shadow/glow` | `0 0 0 4px rgba(45,212,191,0.25)` | hover ring 主色 |

**【论据】**：薄阴影 + 长投影是 Modern SaaS 的视觉签名（vs Material 的硬阴影）。

### 3.5 Dark Mode 边框策略（v1.1 新增 / 同步架构 §4.5 争议点）

> **问题**：dark mode 下 `rgba(15,23,42,*)` 阴影与 `slate/900` 底色对比度极低，阴影"看不见"了——架构 §4.5 争议点明确指出。

**策略**：dark mode 下用**更亮的边框或 outline**替代阴影表达层级：

| Light mode | Dark mode 等价 |
|------------|----------------|
| `shadow/sm` | `border 1px solid slate/700 #334155` |
| `shadow/md` | `border 1px solid slate/700 #334155` |
| `shadow/lg` | `border 1px solid slate/600 #475569` + `shadow/lg-dark`（提高透明度）|
| `shadow/glow` | `outline 2px solid teal/500`（替代 shadow）|

```css
/* dark mode shadow 调亮 */
@media (prefers-color-scheme: dark) {
  :root {
    --shadow-sm: 0 1px 2px rgba(255,255,255,0.04);
    --shadow-md: 0 4px 8px rgba(255,255,255,0.06), 0 2px 4px rgba(255,255,255,0.03);
    --shadow-lg: 0 12px 24px rgba(255,255,255,0.08), 0 4px 8px rgba(255,255,255,0.04);
  }
}
```

**【论据】**：Material Design 3 dark theme guideline 推荐"border + 调亮 shadow"组合。
**【条件】**：卡片 / Popup / 模态框统一遵循；阴影与边框不叠加使用。

### 3.4 渐变

| Token | 用法 | 说明 |
|-------|------|------|
| `gradient/brand` | `linear-gradient(135deg, mint/500 0%, mint/300 100%)` | **仅** Landing page hero 大色块 |
| `gradient/cta` | `linear-gradient(135deg, teal/700 0%, info/500 100%)` | **付费墙主 CTA** / 升级按钮（v1.1 按 §1.5 修正）|

**【论据】**：原 v1 用 mint/500 做付费墙 CTA 渐变起点，违反 §1.5 "品牌色 ≠ 组件色" 原则——付费墙 CTA 是按钮，应使用 teal-700；Landing hero 是品牌色块，可继续用 mint/500。
**【争议点】**：过多渐变显廉价——只在 1-2 个关键 CTA 上用，其他保持纯色。

### 4.2 必备图标清单（v1.0）

| 图标 | 用途 | 名称 |
|------|------|------|
| 📷 相机（线性版）| 主入口按钮 | `icon-camera` |
| 🔲 矩形选择 | 区域截图 | `icon-region` |
| ⏱ 时钟 | 历史库 | `icon-history` |
| ⌨ 键盘 | 快捷键 | `icon-keyboard` |
| ⚙ 齿轮 | 设置 | `icon-cog` |
| ⬇ 下载 | 导出 | `icon-download` |
| 📋 剪贴板 | 复制 | `icon-clipboard` |
| ✨ 闪光 | Pro 升级 | `icon-sparkles` |
| 🔍 搜索 | 历史库搜索 | `icon-search` |
| 🗑 垃圾桶 | 删除 | `icon-trash` |

**【论据】**：v1.0 实际需要 10 个图标，覆盖所有 Popup / 历史库 / 设置 / 付费墙场景。
**【争议点】**：相机是核心入口图标，可否做成"线性相机 + 光圈高亮"——视觉差异化重点。

### 4.3 主入口图标细节（差异化关键）

```
GoFullPage：    实心红色相机，几何粗壮
Shotly：        线性薄荷绿相机，光圈处填薄荷绿半透（mint/100）

视觉效果：
  - 形状相似（仍是相机）→ 零学习成本
  - 颜色对比（红 vs 薄荷）→ 一眼区分
  - 描边粗细（实心 vs 线性）→ 风格差异
```

**【论据】**：这是 PRD §3.2 要求"交互对齐 + 视觉差异化"的核心落地点。
**【条件】**：必须出 3 套备选，主入口图标由 designer 出，PM 双盲评估相似度 ≤ 60% 通过。

## 5️⃣ 组件状态（Component States）

### 5.1 按钮（Button）⚠️ v1.1 主色按架构 §4.5 修正

#### 5.1.1 Light mode（默认）

## 6️⃣ 动效 / 微交互规格

### 6.1 过渡时长（Duration）

| 类型 | 时长 | 缓动 | 例子 |
|------|------|------|------|
| **微动效** | **100ms** | ease-out | hover 颜色切换 |
| **常规动效** | **200ms** | cubic-bezier(0.16, 1, 0.3, 1) | 弹窗出现、按钮按下反馈 |
| **复杂动效** | **300ms** | cubic-bezier(0.16, 1, 0.3, 1) | 模态框滑入、付费墙弹出 |
| **页面切换** | 200ms | ease-in-out | 历史库 ↔ 设置 切换 |

**【论据】**：100-300ms 是 Material Design 3 motion timing 的现代版本。
**【争议点】**：太慢影响操作效率；太快没反馈感。100/200/300 是三档经验值。

### 6.2 微交互清单

| 场景 | 动效 |
|------|------|
| **截图按钮按下** | 50ms 缩放 0.95 → 100ms 回弹 1.0 |
| **预览窗口滑入** | 右下角 300ms ease-out 滑入 |
| **历史库缩略图 hover** | 100ms 高亮边框 (`shadow/glow`) |
| **付费墙弹出** | 200ms 渐变 + 5% 缩放（避免突兀）|
| **错误 Toast** | 顶部滑入 200ms，停留 5-8s，渐变消失 |
| **区域截图框选** | 框线实线 1.5px + 半透填充 `mint/100` |

### 6.3 Dark Mode 切换动效

背景渐变过渡 200ms，避免突兀跳转：

```css
:root {
  --bg: #F8FAFC;  /* light */
  --fg: #0F172A;
}
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0F172A;  /* dark */
    --fg: #F1F5F9;
  }
}
body { transition: background-color 200ms ease; }
```

#### 8.1 v1.1 新增：「品牌色 vs 组件色」双层体系说明

**为什么分两层？**

| 场景 | 用品牌色 mint/500 #2DD4BF | 用组件色 teal-700/500 |
|------|--------------------------|----------------------|
| 产品 logo | ✅ | ❌ |
| Landing page hero | ✅ | ❌ |
| Marketing 配图 | ✅ | ❌ |
| Chrome Web Store 商店素材 | ✅ | ❌ |
| Popup 主 CTA 按钮 | ❌ | ✅ |
| Options 链接 | ❌ | ✅ |
| 输入框 focus ring | ❌ | ✅ |
| Toast / 提示图标 | ❌ | ✅ |

**【论据】**：品牌色 #2DD4BF + 白字 2.71:1 ❌ 未达 WCAG AA；用作品牌大色块 + 黑字 11.78:1 ✅ 完全达标。组件层必须用更深一档 teal 才能保证文本可读性。
**【条件】**：设计稿中如出现品牌色用于按钮 / 链接 / 文字，PM 评审一票否决。
**【争议点】**：设计师可能觉得"按钮不就是品牌色吗" —— 需要出稿前明确传达本原则（参见 §1.5 决策记录 + 设计师协作清单 §9）。

**相似度预估**：60%（在边界线）— 需要设计师出 3 套差异稿，PM + 外部独立评估双盲确认 ≤ 60%。
